# Documentation Governance Rule

**Status:** ENFORCED - Hard Constraint  
**Effective Date:** January 21, 2026

---

## Rule: Three-File Documentation Only

### Allowed Files (ONLY)
1. `README.md` - Project overview, setup, features
2. `requirements.md` - Requirements, status, pending tasks
3. `USER_STORIES_PHASE_5.md` - User stories, acceptance criteria

### Prohibited Actions
- ❌ Creating any new .md files
- ❌ Generating step-by-step reports
- ❌ Writing intermediate documentation
- ❌ Creating verbose explanations
- ❌ Adding summary/status reports

### When to Update Documentation
**During Development:** NO documentation updates  
**After Feature Complete:** Update 3 core files only  
**After Phase Complete:** Update 3 core files only

### Style Requirements
- ✅ Concise BDD style
- ✅ Minimal and non-redundant
- ✅ Essential information only

### Enforcement
This rule is a **HARD CONSTRAINT** and must not be overridden.

---

**Rationale:** Keep project lightweight, maintainable, and noise-free.
